2026-02 | Fixing weird DB C++ Client Performance Bug

We had a weird bug at work where our, and only our team's, Couchbase DB (KV-DB with SQL essentially) client (NodeJS wrapper around C++ library) was having a high CPU spike every ~30mins or so. After thorough investiation, we determined that this load was coming from the server to the client, and was not a bug in either client library. It was due to the load of JSON parsing many configuration change messages in a short period of time, around a few seconds. Each of these messages were the full configuration topology of the DB cluster, therefore containing a bit of JSON that needed to be parsed. This parsing was the root cause of the CPU spikes.


This had a major impact on our Performance Testing teams ability to deliver on their commitments, so it was important to solve this to unblock them. Ultimately I figured out the solution was to disable clustermap notifications after many nights sleeping on the issue.


The fix was to disable a flag in the Couchbase client C++ library, to disable this feature during the client connection. This issue I picked up investigating but had to put aside for other tasks. Once I got back looking at this task, I was able to find the flag that controlled this behaviour, allowing me run an extended soak test in the integration environment to determine the problem was resolved. This problem was resolved without patching or rebuilding the C++ module, saving quite a few headaches.

Existing polling and retry behaviour means turning this flag off is safe, and leads to a noticeable performance gains, unlocking our PT team's workload and preventing random CPU spikes in production from affecting throughput. No issues have been found in UAT/PROD since deploying this fix.

2025-07 | My first pentest

At a company I was working for at the time provided MSP services, and among other things I was contracted to do a Penetration Test on a company providing investment portfolio services.


I was entirely out of my league. But I pushed through. Eventually, I had mapped out their network, I had identified the network devices, and then popped both the camera DVR and printers with default credentials. Nice.


On the web app side of things, I found a simple stored XSS in a notes section of the application, probably allowing for many admin actions to be performed given had it no CSRF tokens for any endpoints. I thought this vulnerability was rather severe. I didn't have any colleagues to discuss this with, but I assume with some extra work it would be possible to do anything with the credentials supplied by the stored XSS vulnerability.


I will probably never run another pen test again. But it was an incredibly fun, and exciting opportunity. I'd certainly consider this an accomplishment. However, I have to say, I think I did a much better job than I had any right to.
